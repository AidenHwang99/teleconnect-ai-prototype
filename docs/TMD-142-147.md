## 2. 信息架构、顶部入口和固定开关

### 2.1 会话类型

| 会话 | 界面与行为 |
| --- | --- |
| OSS agent Integration | 群聊：群聊信息、成员及附件内容；@支持成员和我的AI，不共用AI专属业务首页 |
| Girum Mesfin Agonaf | 私聊：联系人头像/消息、私聊输入；@仅显示我的AI，不显示全部/成员标签 |

私聊和群聊不增加AI任务看板/业务快捷按钮。原有群成员操作、聊天文件、消息和AI私有草稿保留。

### 2.2 顶部按钮

从左至右：**主动服务（时钟）→ 我的业务（业务图标）→ 知识案例（书本）**，后面保留返回对话/模式及更多菜单。

- 三个模块各自有“固定顶部”开关，位于模块标题区；互相独立。
- 当前默认固定已支持的功能。按演示用户及AI范围分别保存；全局入口单独保存。
- 关闭仅隐藏快捷图标，不删除模块，不清除数据，不自动标记已读。
- 剩余按钮靠右连续排列，不保留空位。仅主动服务开启时，它占据靠近返回按钮的可用位置。
- 知识案例仅为原有知识案例能力的授权Agent提供，不给其他AI伪造知识库。
- 原型固定偏好保存在小型独立localStorage中；浏览器拒绝保存时当前页面仍生效并提示。

### 2.3 更多菜单

保留原有菜单；主动服务、我的业务紧邻排列在知识案例上方。没有知识案例的Agent，将主动服务、我的业务放在菜单末尾。关闭顶部固定不影响菜单入口。知识案例菜单项右侧不再展示案例数“2”；案例列表自身的数量和分页仍保留。

## 3. 我的业务：统一列表、状态和关联筛选

### 3.1 主入口

客户端将“我的业务、任务看板、待我审批”三个重叠入口合为**我的业务**。沿用142白色业务列表、标题、任务编号、状态、摘要、行内操作及分页布局。审批作为业务状态、与本人关联及详情中的能力存在，不另建平行客户端页签。后台任务看板仍保留。

来源包括流程编排、主动服务运行、会话协作；展示可授权的数据及适用操作。审批关联所属任务，不把同一任务和审批单重复计为两项业务。

### 3.2 搜索与筛选布局

搜索框在标题下第一行；主要筛选在第二行；高级筛选默认折叠，通过“更多筛选”展开。主动服务和AI助手采用相同搜索宽度、标签、控件高度、间距及重置逻辑。

- 搜索：任务名称、编号或负责人；搜索按钮/Enter应用条件。
- 外层：**业务状态**、**与我相关**；全局入口按授权提供AI筛选，AI入口固定当前AI。
- 高级：来源、任务时限、SLA时限、授权部门、指定成员、参与职责、创建日期区间、排序等，按角色提供。
- 已选条件用可关闭摘要显示。收起不清除条件；重置清除筛选，保留入口AI范围及页面基本设置。
- 条件变化回到第一页；数量与分页基于同一份授权后过滤的数据。
- 原“全部业务/待处理/已提交完成”三个Tab已由状态筛选替代，避免两个入口表达同一条件。

### 3.3 状态与关联是两个维度

| 字段 | 当前选项/含义 |
| --- | --- |
| 业务状态 | 全部状态、待处理、进行中、待审批、待补充、已完成、已归档、异常 |
| 与我相关 | 不限关联、任一关联、本人负责、本人审批（有能力时）、本人参与 |
| 指定成员 | 当前授权范围内的具体成员；与“本人关联”条件互斥，选择一方清除另一方 |
| 参与职责 | 选择具体成员后，明确按负责人/审批人/参与人检索 |
| 任务时限 | 普通任务截止时间，例如已经逾期 |
| SLA时限 | OSS节点SLA的正常/临期/逾期等，不能用普通任务截止时间冒充 |

“与我相关”指任务和登录用户的关联，不是扩大人员授权。“本人参与”不能把仅负责或审批的所有任务混入参与结果。“不限关联”仍受数据权限约束。“待我处理”可理解为本人负责且当前需要处理/补充；“待我审批”是本人被指定审批且审批尚待处理。两者不是同义状态。

当前界面将旧内部终态`已终止`显示为“已归档”，用于兼容既有数据；此显示更名不是已经实现独立归档生命周期的接口。生产需明确归档与取消/终止业务状态的映射。

### 3.4 列表操作

根据当前状态、负责人、指定审批人和权限显示：开始处理、更新进展、转派、任务详情、联系/催办、AI答疑、查看流程、审批/执行与验证等。业务列表页签精简不删这些操作。

转派恢复142选人流程：选择具备相应AI/领域资格的其他处理人 → 输入原因 → 校验当前任务和候选人 → 按原规则直接提交或申请审批 → 更新负责人和历史。不能转派给自己或越权人员；截止时间不重置。新负责人及当前节点联系人需要联动，原负责人不可继续获得不应保留的处理权。

## 4. 权限、统计和数据范围

权限拆分为角色、授权AI、授权部门、本人关系、审批能力、操作能力、组织筛选能力。管理员名称不代表无限访问。

| 身份/条件 | 可见范围 | 筛选及动作 |
| --- | --- | --- |
| 普通成员 | 本人负责、参与、申请或被指定审批的授权业务 | 不显示组织及成员筛选；审批能力独立判断 |
| 部门负责人 | 授权部门及额外授权的本人相关业务 | 单部门固定展示，多部门下拉；成员随部门变化 |
| 有限管理员 | 明确授权部门与AI范围 | 不可访问未授权AI或组织 |
| 指定审批人 | 对被指定的任务执行审批，需审批能力 | 不因一条跨部门审批获得整个部门数据 |
| 可见但非本人服务 | 允许的只读详情 | 不因可见而获得编辑、运行、暂停、删除权 |

查询顺序必须是：身份/能力与数据授权 → 用户筛选 → 排序/统计/分页。详情和动作再次校验授权；伪造筛选值、旧链接或ID不能扩大范围。换身份、换部门后清理失效成员/AI条件，红标和消息同时重新计算。

原型演示账号由本地设置切换，**不是生产登录和鉴权**。生产必须服务端执行上述判断；不能信任前端角色字段、隐藏按钮或localStorage。

统计口径：业务数按唯一业务项；通知数按唯一通知事件；完成结果数按唯一完成结果；运行会话数按session。它们不能互相相加或用同一个数字代替。

## 5. 任务详情、AI答疑与SLA节点

### 5.1 详情复用142

页面命名使用**任务详情**，保留142的任务标题、状态/编号、任务信息、诊断与处理建议、处理时间线和底部操作。补充负责人、责任部门、关联实例、修订、审批详情、SLA信息及催办入口。不同入口打开同一任务，数据与可执行动作一致。

详情抽屉限制在teleConnect的右侧AI内容区域，位于会话标题下方、贴内容区右侧，不贴整个桌面最右边；缩放/窗口尺寸变化后重新定位。关闭返回原页面和上下文，避免覆盖整个客户端壳层。

### 5.2 AI答疑

沿用142“AI答疑”上下文卡：任务编号、标题、摘要、带入范围、返回我的业务、查看任务，以及“出了什么问题/判断依据是什么/下一步怎么排查”等引导。多会话Cowork结果使用相同层级，分析结果及运行信息可展开，保留原复制、反馈、分享、来源和运行操作。

AI答疑、运行成功或审批通过均不等于设备已修复、工单已关闭。完成必须等待对应执行及验证条件。

### 5.3 SLA流程节点

只展示OSS工单返回的“SLA流程节点”，示例为：

**工单建立 → 分派 / 诊断 → 故障处理（当前） → 修复验证 → 关闭**。

可点击节点查看负责人、开始/完成时间、独立截止时间及节点状态。工单总SLA与当前节点SLA分别说明。示例节点明确是模拟返回；真实返回缺失时显示未提供，不推断。已移除把“FBB②…18个编排节点”混入SLA区域的设计；原业务“查看流程”功能仍保留，二者语义不同。

## 6. 主动服务：配置、运行和结果

### 6.1 列表与筛选

- 所有授权AI沿用主动服务入口、模板与自定义创建；进入AI范围固定该AI。
- 全局入口汇总授权AI；创建时明确选择AI，不能继承一个无关的隐藏AI。
- 外层：搜索、服务视图、服务状态、更多筛选、重置。
- 服务视图区分服务列表、主动服务模板、已完成运行；服务状态用于启用/暂停/草稿/结束等，不重复设置“已启用”Tab。
- 高级条件：创建来源（模板、自定义、会话）、执行频率、最近执行结果、授权部门/创建人、下次执行日期范围等。
- 普通成员不显示跨组织筛选。其他人的服务即使可见也保持只读。模板仅显示可调用AI及启用模板。
- 业务、服务、AI范围和用户的筛选上下文独立；切回来恢复该范围的筛选/分页。收起高级条件后显示已选摘要；非法日期区间明确提示。

### 6.2 操作及不变量

| 操作 | 当前交互 | 必须保持 |
| --- | --- | --- |
| 模板/自定义创建 | 原编辑表单，名称、指令、范围、计划、时区等确认后保存 | 保存配置版本，明确AI及负责人 |
| 立即运行 | 创建单次运行；已有排队/执行/待补充运行则返回在途运行 | 不重复生成，不改变原周期 |
| 已暂停时立即运行 | 确认只执行一次 | 仍保持暂停，不恢复定时计划 |
| 编辑 | 保存新配置版本；未保存切换有提示 | 旧运行配置快照不改写 |
| 暂停/恢复 | 控制未来触发并计算后续计划 | 暂停不取消在途运行，不批量补跑暂停期间任务 |
| 分享 | 配置只读快照、接收者、有效期与撤销 | 不自动创建对方任务或赋予执行权限 |
| 删除 | 展示对象及后果，确认后移出有效列表 | 历史运行、来源审计及结果保留；在途取消另行操作 |

更多操作浮层独立于表格滚动容器，不被粘性列遮住；靠近底部向上展开，Esc/外部点击等可关闭。

### 6.3 运行状态

排队 → 执行中 → 成功/部分成功/失败/超时/待补充/已取消。待补充提交有效信息后继续同一运行；失败或超时可按策略重试；重试保留Run ID及历史，尝试次数增加，原型最多3次。取消后的迟到结果不应覆盖取消终态。

展示运行阶段和加载动效，不用虚假百分比。成功表示本次AI结果生成完成；部分来源失败必须说明缺失范围。无数据、无权限和失败区分。原型使用本地计时演示，页面退出不能提供真实后台调度。

## 7. AI助手、未读和气泡

### 7.1 内容与分类

AI助手保留全部授权历史提醒，卡片明确区分“我的业务”和“主动服务”，不显示“主动服务（定时任务）”后缀。业务包含分派、进度、审批、SLA及会话协作；主动服务包含计划任务/运行结果。

搜索和提醒分类、授权AI、阅读状态位于外层；日期、任务状态、业务来源、SLA或运行结果等放在更多筛选。切换分类清理不适用条件。卡片自适应列数，正文可换行，长文可展开，不通过固定高度截断关键操作。

ERP、telebirr、会议、邮件示例保留；仅有OSS权限的身份不会显示Big Data数据。通过演示设置中的“142内容与多AI示例”体验授权管理员视图，示例默认暂停或明确标记，避免自动反复产生结果。

### 7.2 单一未读口径

- 气泡、AI助手、各AI红标来自相同授权通知源，按通知ID去重。
- 只保留红色未读数字，移除黄色感叹号、绿色数量和橙色SLA数量等并行提示；SLA风险仍在消息正文及详情显示。
- “我的AI”分组收起时只显示有未读的红点；展开后各AI显示各自红色数量，不重复AI助手摘要。
- 未读包含业务、审批、SLA、主动服务和协作通知；同任务不同事件可以分别未读。
- 打开列表、筛选、固定开关、折叠菜单不标记已读；从单条提醒进入详情只消费该通知。
- 直接从业务列表打开任务详情时，可以消费该任务的普通任务/审批消息，但不把其他SLA提醒、其他任务或AI一起清除。
- 关闭完成提示只隐藏提示；已读与任务完成、SLA风险、系统投递状态独立。
- 当前原型已读按演示用户保存；后台审计不能替客户端用户标记已读。

### 7.3 气泡布局和多会话协作

展开菜单最上部为**正在协作 → 我的业务**，下方为**我的AI**。我的AI悬浮展开沿用142交互。

正在协作支持折叠/展开和查看全部，按AI和会话分组。多AI、多会话可以同时有运行，展示名称和阶段；点击会话精确到该AI的该session及相关run，不只是打开AI首页。运行中显示动效，完成后给出任务完成文字和红标，不叠加绿色勾选徽章。

切换会话保留当前草稿和附件；历史、重命名、删除、分享继续关联准确session。删除一段历史不影响其他会话，不能借跳转把别人的运行带入当前身份。原型重载中的运行有恢复/中断语义，不声称在关闭网页后仍执行。

### 7.4 演示与浏览器差异

左下角“147 · 完整流程演示”和演示设置提供：多AI内容、角色效果、5条完成提醒、并行协作、运行状态及通知效果。

“5条完成提醒示例”为OSS3条、Big Data1条、teleConnect1条；重复载入不重复创建，仅恢复本组未读并保留其他历史。红标统计全部未读，实际数字可能大于5。Chrome、Codex预览、file://、localhost、127.0.0.1和不同端口的存储不应假定共享。GitHub Pages新来源也会有独立演示状态。刷新更新代码，不等于重置已读。

## 8. 审批、SLA与联系催办

### 8.1 审批

任务详情显示申请操作、申请人、指定审批人、风险依据、影响范围、输入快照、截止时间、状态和审批记录。指定且有能力的审批人可提交意见；通过后进入待执行/验证，不能直接当作业务完成。拒绝、补充和重复提交需遵循当前状态与修订校验。

审批结果通知指向同一任务/审批记录。当前任务数量不因挂审批单重复累加；处理权限和审批权限独立。转派按原策略审批，审批中SLA继续计时。

### 8.2 SLA来源和提醒

OSS提供工单总截止、当前节点、节点截止、节点负责人、联系人、修订及同步时间。临期为进入阈值但未超时，逾期为超过截止且未完成；“时限提醒”是通知类别，不是第三种SLA状态。节点时限优先表达当前处理责任，总SLA表达工单整体约束。

临期与逾期条件可以清除/切换/重置；阅读提醒、审批等待、催办、转派不暂停或重置SLA。过期联系人快照在演示中可自动模拟刷新；生产必须调用真实查询并处理失败，不能仅修改时间戳。

### 8.3 渠道选择及完整流程

| 联系资料 | 可用路径 | 展示步骤 |
| --- | --- | --- |
| 已验证teleConnect账号 | 快速消息 | 编辑消息 → 收件人/内容预览 → 明确确认 → 模拟回执与记录 |
| 有邮件 | AI起草邮件 | 输入写作要求 → 生成主题/正文 → 编辑 → 预览 → 确认发送（模拟） |
| 有电话 | 快速拨号、AI起草短信 | 号码确认/交接拨号器示意，或短信编辑/段数估算/预览/确认 |
| 信息不足 | 补充/同步资料 | 说明缺少哪项，不生成虚假可用渠道 |

联系对象为当前节点责任人，不一定是工单最初负责人。可按授权为客户联系人创建会议邀请并选择可用渠道，不自动给所有人群发。任务结束、权限变化、联系人更新等在确认前重新检查。

### 8.4 会议邀请

在消息/邮件/短信草稿中快捷创建会议，可设置主题、时间和时区，将邀请文字及链接插入草稿。展示邀请者、Title、Ethiopia Time（GMT+03:00）、Meeting ID和Join链接。用户提供的会议链接仅作格式参考，不重复使用为每次新会议。创建/编辑草稿与发送分开；取消发送不会伪造已送达。

记录渠道、目标、内容快照、会议关联、操作人、时间、发送/失败/模拟回执及重试。短信段数是估算，真实编码、费用和投递由网关决定。纯HTML未发出真实teleConnect消息、邮件、短信或电话，未创建真实会议。

## 9. 后台管理、任务看板和审计

### 9.1 后台任务看板

保留统一统计与任务跟踪能力，以表格、搜索、授权部门/成员筛选、状态/来源/AI/日期及分页为主，详情按需展开；不把大量任务全部平铺长卡片。看板可作为辅助视图，不替代大数据量列表。详情复用同一业务、审批、SLA和运行关联，角色过滤与统计同源。

### 9.2 主动服务运行记录

表格展示：服务名、Run ID、AI、责任部门、状态、触发方式、发起人、服务负责人、开始/结束时间、耗时（含排队/等待）、配置版本。手动发起人与负责人分列；系统计划标记系统调度；历史字段缺失显示未记录。

支持名称/编号、AI、状态、触发方式、日期；有组织权限时支持授权部门、负责人和发起人。先权限过滤再统计分页，支持10/20/50条分页。保留运行详情、来源、补充、重试历史及模拟调度。

### 9.3 创建来源会话与Q&A Log

后台不提供“在会话中继续”跳客户端。主动服务实例的**创建来源会话**进入后台Audit Center → Q&A Log，打开Dialogue Details右侧抽屉。

- 服务创建会话：展示哪个会话如何形成服务，包括提出需求、澄清范围/时间、计划回显、用户确认及最终创建配置。
- 运行问答记录：展示某次运行请求、补充、结果、来源和执行时间线。不能把运行日志冒充创建聊天。
- 列表保留Session Name、Q&A Type、Agent Type、Chat mode、Operator Name、Operator Phone、Session Start/End Time及Action，并关联Service ID、Run ID、Trace ID。
- 对话按用户/AI分侧展示，包含消息时间、创建者、会话标识和确认配置版本。没有数据不补造。
- 新建时保存来源快照；后续编辑不能改写原创建证据。后台表单创建明确标记，旧记录未保存来源明确说明缺失。
- 原型LOCAL Trace与示例对话用于演示。生产应以真实session_id/message_id范围、service_id、确认消息、版本和trace_id关联，并做服务端审计授权与脱敏。

## 10. 业务实例、场景模板与配置检查

### 10.1 实例发布场景模板

业务实例增加发布为场景模板流程：选择实例 → 检查可发布条件 → 填写模板名称/分类/说明、可参数化项 → 检查范围/敏感实例信息 → 预览 → 确认发布版本。模板复用流程配置与允许的参数，不复制工单实时状态、历史审批结论、执行结果或实例责任人私有信息。

已有实例固定原快照；模板后续升级不悄悄改变已运行实例。冲突、缺项、无权限和检查不通过应反馈明确原因。新实例使用模板时重新选择对象、角色和参数，不沿用原运行授权。

### 10.2 检查通过的边界

复用1019的结构化检查思路，将配置检查、试运行、审批和真实执行分别表达。检查内容包括结构连线、必填项、对象/能力绑定、参数与输入、审批/负责人、异常分支及可能的路径风险。

检查报告显示项、级别、定位与整改建议。配置修改后旧检查结论失效；试运行固定版本、输入、路径、来源及结果。配置检查通过仅说明当前静态条件满足，不表示真实数据源已连通、真实命令已执行或生产审批已通过。

## 11. 文件、上下文、分享与原有聊天

文件AI选择器修复滚动裁切，显示于可见浮层。文件问答选AI后沿用独立窗口和私有草稿流程；群聊发送前确认，不自动把AI回答发给所有成员。

文件有解析状态、版本、来源与引用位置。原型支持有限的DOCX/XLSX/PPTX/TXT/CSV提取；复杂文件、旧Office格式、PDF/OCR、公式计算等需真实解析服务。处理失败和无权限不可伪装为已成功解析。附件数量/大小遵循原型当前限制，生产需统一服务端校验。

私有草稿允许改问题、改回答、重生成、取消和确认发送；问题变更后旧答案需重新生成或明确过期。会话分享为消息快照，答案/配置分享只读；有效期、撤销及接收者权限独立，不转移文件权限。跨浏览器分享依赖后续服务端存储，当前本地链接不能等同跨设备共享。

输入区不再常驻“上下文：仅本次问题与附件”“文件与解析状态”两个占位按钮；相关能力通过适用的附件/AI范围设置及文件入口呈现。原有聊天消息、文件、历史与分享能力保留。
