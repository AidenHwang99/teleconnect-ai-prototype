# teleConnect 148 更新说明与验收流程

更新日期：2026-10-30。以147完整文件为基线新增148，142–147均保留。142到147的历史设计与交互说明继续见 [142→147 TMD](teleConnect_147_TMD_142之后全部更新.md)。涉及提醒、筛选、浮球和会话未读的规则，以本文为准。

## 一、AI助手恢复142卡片布局

保留按日期分组、卡片时间、所属AI、标题、摘要、状态及底部详情操作。宽区域三列、中等两列、窄区域一列；长摘要提供“展开全文”，不删除原始内容。保留Big Data经营简报、telebirr分析、OSS业务、主动服务、审批与SLA等既有示例，展示范围受当前身份权限约束。

外层只显示搜索、提醒分类、更多筛选、重置。分类为全部提醒、我的业务、主动服务、其他事件；更多筛选保留授权AI、阅读状态、事件类型、SLA、部门、日期等条件。筛选组合取交集，不扩大授权范围；重置清除筛选而非改变身份。隐藏条件生效时，“更多筛选”显示条件数量。AI助手仍是跨授权AI的提醒汇总，不替代Agent业务列表。

## 二、Agent模块与紧凑筛选

我的业务、主动服务通过Agent进入，数据固定为该Agent，更多筛选不再展示AI下拉框。任务按所属AI筛选，不能因旧会话关联而混入其他AI业务。无Agent上下文时先选择有权限的AI。

我的业务外层保留搜索及业务状态；与我相关、来源、SLA、部门、成员、日期、排序等移入更多筛选。主动服务外层保留搜索及服务状态；服务视图、执行计划、创建人等移入更多筛选。原模板、已完成结果视图及运行记录能力保留。列表去掉重复的“流程编排 · OSS agent”等来源行，任务详情仍保留来源证据。

更多菜单移除独立“已完成任务”入口；主动服务、我的业务、知识案例及独立固定开关保留。固定图标顺序和关闭后自动补位沿用147。群聊和私聊不因此增加Agent业务图标。

## 三、正在协作包含主动服务

浮球菜单去掉“我的业务”项，顶部为可折叠的“正在协作”，下面保留“我的AI”及原有浮球工具。会话协作与主动服务统一展示，区分类型，显示名称、所属AI和运行状态。计划触发或立即运行会创建运行记录，并在浮球出现；完成后同一运行记录退出运行区并进入完成结果。运行中保留动效，失败或待补充仍有处理入口，不能伪装为成功。

会话条目跳转对应Agent的对应会话；主动服务运行条目打开该次运行详情。未完成、等待、断线和失败不计入已完成数量。

## 四、完成提醒原位展开

右下角“任务已完成”提供展开/收起按钮，展开后在同一弹框内列出当前身份可见的全部完成结果，包括已读结果。条目按完成时间排序，较多时分页加载并在弹框内滚动。点击某一项展开内容和运行记录，不导航到AI助手、我的业务或主动服务。

仅在实际展开某项结果后标记该项已读；展开总列表不批量清除未读。结果内容与现有完成记录共用数据，不另建重复任务。气泡内阅读与Chat History、Agent数字、模块提醒同步。

## 五、数字口径与蓝点

| 位置 | 统计对象 | 阅读后的变化 |
|---|---|---|
| Agent外层数字、浮球我的AI中对应数字 | 含未读Cowork完成结果的会话数 | 一个会话的所有完成结果读完后减1 |
| Chat History蓝点 | 此会话仍有未读Cowork完成结果 | 最后一项读完后移除蓝点，保留已完成文字 |
| 浮球红标及完成提醒未读数 | 当前身份有权查看的未读完成结果条数 | 阅读一项减1 |
| AI助手数字 | 所有授权未读事件，包括业务、审批、SLA和服务提醒 | 阅读对应事件后减少 |
| 主动服务／我的业务顶部红标 | 对应模块的未读事件数 | 沿用分类定位与逐项阅读 |

例如一个会话产生两条完成结果：Chat History只有一个蓝点，Agent数字为1，完成弹框显示两条结果。读完第一条时该会话蓝点仍在；读完第二条后蓝点消失。不同统计对象不强制显示同一数字。Agent数字点击后打开该Agent历史列表；点击有蓝点会话定位最新未读协作结果，不随机打开其他会话。

权限先于筛选与统计执行。切换身份后重新计算可见完成记录与计数；不能沿用上一身份结果。浏览器、域名及版本的本地状态独立，不同浏览器操作后数字可以不同。

## 六、可重复演示

1. 左下角打开“148 · 本轮交互演示”，点击“建立本轮场景”。按当前授权AI新增三条会话、四项协作运行和一项主动服务；其中一个会话有两项运行，已有内容不被清空。
2. 浮球展开“正在协作”，检查会话和主动服务同时出现；点击标题可折叠。
3. 再打开演示，点击“模拟本轮任务完成”。演示场景通过按钮推进，避免还没看清就结束；普通服务仍按原有模拟执行阶段自动完成。
4. 在右下角展开结果，点击结果阅读，检查主页面不切换。Agent中打开Chat History，观察蓝点与外层数字对应。
5. 同一会话两项结果逐项阅读，核对数字只在全部读完后减1。不同AI可分别检查；多AI效果需要使用拥有多AI权限的演示身份。
6. 可“新一轮演示（保留历史）”；刷新造成演示运行中断时可恢复该轮运行。原有完整流程演示、角色示例、转派、审批、催办、来源审计和通知说明仍保留。

## 七、验证与实现边界

本轮25项专项检查、12项原有能力保留检查、15项运行回归检查通过，共52项。涵盖Agent范围、筛选交集、Big Data示例、SLA/部门过滤、服务进入协作区、同会话多结果计数、蓝点与数字、精确会话跳转、原位阅读、身份隔离与菜单保留。

浏览器实际检查了普通服务“立即运行→排队→自动完成→弹框内阅读”，完成未读5→4时主页面保持主动服务；检查了三条历史蓝点与Agent数字3对应，打开指定会话后同步减为2。检查记录只说明交互原型，不能替代真实接口验收。

OSS、AI执行、调度、审批、消息/邮件/短信、拨号、会议及系统通知仍为本地模拟或效果说明。页面关闭时不执行真实计划。接入生产时应由服务端提供权限校验、任务事件、幂等运行ID及跨设备阅读状态；本原型不新增真实外发操作。
