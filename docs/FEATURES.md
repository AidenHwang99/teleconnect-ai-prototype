## 2. 导航、会话类型和固定图标

- **群聊** OSS agent Integration：群成员、群消息、附件及 @成员/@AI；保留私有草稿确认后发送。
- **私聊** Girum Mesfin Agonaf：联系人及私聊消息；@ 仅展示我的 AI，不展示成员和全部分类。
- **AI 会话**：独立 Chat/Cowork 上下文、我的业务、主动服务及当前 Agent 的领域能力。
- **AI 助手**：授权范围内的提醒和运行快照汇总，不另建重复的客户端任务看板/审批 Tab。

顶部从左到右为：**主动服务 → 我的业务 → 知识案例**，之后为返回对话/模式及更多菜单。各模块标题旁有独立“固定顶部”开关；隐藏图标不删除功能、不清数据、不消费未读。剩余图标连续靠右排列，无占位空隙。知识案例按 Agent 原有能力及权限展示，不虚构其他领域知识库，菜单不显示多余案例数量。

更多菜单保留 New Chat、Chat History、Search Chat、Refresh Page 等；主动服务、我的业务在知识案例上方，没有知识案例时置于菜单末尾。群聊和私聊不显示这些 AI 专属快捷按钮。“会话列表”不再作为对话正文中的第二个历史入口；会话历史从 Chat History 进入。

## 3. 我的业务：状态、环节与职责

“我的业务”统一承接处理、审批及追踪；保留任务标题、编号、优先级、SLA、摘要、负责人、操作与分页，不因合并入口删除功能。来源包括流程编排、会话协作及主动服务运行；审批关联原业务，不重复算作另一项业务。

### 3.1 三个独立维度

| 维度 | 说明及选项 |
| --- | --- |
| 整体状态 | 未开始、进行中、已完成、已取消；全部状态在首位 |
| 当前环节 | 等待处理、正在执行、等待审批、等待补充、执行暂停、执行异常 |
| 与我相关 | 不限关联、待我处理、待我审批、待我补充、本人负责、本人审批、本人参与 |
| 归档状态 | 全部记录、未归档、已归档；归档不等于取消或成功 |
| SLA 状态 | 正常、临期、逾期等，独立于整体状态和个人职责 |

例如：一个故障处理业务整体仍是“进行中”，当前环节是“等待审批”；指定审批人看到“待我审批”，其他有权查看的人不会被标成待我审批。通过审批只允许进入执行/验证，不自动完成业务。阅读清除未读，不改变待办义务。

等待分派后的处理、等待补充和等待审批均属于尚未完成的业务。异常/暂停作为当前环节展示，不能冒充完成。旧存档若只有旧终止/归档标记、没有原始终态，显示“状态待核对 + 已归档”，不猜测已完成或已取消。

“待我处理”表示本人负责且当前处于等待处理或正在处理环节；“待我审批”仅匹配本人为指定审批人且当前等待审批；“待我补充”匹配本人负责且当前等待补充。“本人负责/审批/参与”是关系查询，不限定任务仍需操作。AI自动运行的协作或定时服务不因用户是所有者就标成待我处理。

### 3.2 紧凑筛选及列表操作

第一行宽搜索框与搜索按钮，第二行整体状态、更多筛选、重置。当前环节、与我相关、归档、来源、SLA、授权组织/成员、日期与排序放入高级筛选。Agent入口固定该AI，不再显示重复的AI筛选及每行“流程编排 · OSS Agent”。

条件取交集，改变条件返回第一页；收起不清条件，已选条件提供摘要及清除入口。重置保留当前入口AI及权限边界。列表、数量、分页使用同一授权后筛选集合。分页最少5项，保留10/20/50/100等原有选择。

保留开始处理、更新进展、转派、任务详情、联系/催办、AI答疑、查看流程和审批动作。转派可以选择授权候选人、填写原因，按原策略直接提交或申请审批；不能越权或转给自己，不重置SLA，负责人和处理记录同步更新。



## 4. 权限、统计和数据范围

权限拆分为角色、授权AI、授权部门、本人关系、审批能力、操作能力、组织筛选能力。管理员名称不代表无限访问。

| 身份/条件 | 可见范围 | 筛选及动作 |
| --- | --- | --- |
| 普通成员 | 本人负责、参与、申请或被指定审批的授权业务 | 不显示组织及成员筛选；审批能力独立判断 |
| 部门负责人 | 授权部门及额外授权的本人相关业务 | 单部门固定展示，多部门下拉；成员随部门变化 |
| 有限管理员 | 明确授权部门与AI范围 | 不可访问未授权AI或组织 |
| 指定审批人 | 对被指定的任务执行审批，需审批能力 | 不因一条跨部门审批获得整个部门数据 |
| 可见但非本人服务 | 允许的只读详情 | 不因可见而获得编辑、运行、暂停、删除权 |

查询顺序必须是：身份/能力与数据授权 → 用户筛选 → 排序/统计/分页。详情和动作再次校验授权；伪造筛选值、旧链接或ID不能扩大范围。换身份、换部门后清理失效成员/AI条件，红标和消息同时重新计算。

原型演示账号由本地设置切换，**不是生产登录和鉴权**。生产必须服务端执行上述判断；不能信任前端角色字段、隐藏按钮或localStorage。

统计口径：业务数按唯一业务项；通知数按唯一通知事件；完成结果数按唯一完成结果；运行会话数按session。它们不能互相相加或用同一个数字代替。

## 5. 任务详情、AI答疑与SLA节点

### 5.1 详情复用142

页面命名使用**任务详情**，保留142的任务标题、状态/编号、任务信息、诊断与处理建议、处理时间线和底部操作。补充负责人、责任部门、关联实例、修订、审批详情、SLA信息及催办入口。不同入口打开同一任务，数据与可执行动作一致。

详情抽屉限制在teleConnect的右侧AI内容区域，位于会话标题下方、贴内容区右侧，不贴整个桌面最右边；缩放/窗口尺寸变化后重新定位。关闭返回原页面和上下文，避免覆盖整个客户端壳层。

### 5.2 AI答疑

沿用142“AI答疑”上下文卡：任务编号、标题、摘要、带入范围、返回我的业务、查看任务，以及“出了什么问题/判断依据是什么/下一步怎么排查”等引导。普通Cowork使用左右对话与折叠执行过程；任务AI答疑继续保留原上下文卡和相关操作。

AI答疑、运行成功或审批通过均不等于设备已修复、工单已关闭。完成必须等待对应执行及验证条件。

### 5.3 SLA流程节点

只展示OSS工单返回的“SLA流程节点”，示例为：

**工单建立 → 分派 / 诊断 → 故障处理（当前） → 修复验证 → 关闭**。

默认选择当前节点；点击任一节点后，下方**仅保留一张详情卡**，替换为所选节点的负责人、开始/完成时间、独立截止时间、SLA状态与说明。当前执行节点持续保持“当前节点”标识，所选节点另用描边区分；两者不混淆。重新打开任务默认回到当前节点。查看不推进任务、不审批、不改变SLA计时，不能绕过详情授权。缺失时间与负责人显示OSS未提供；未开始节点如实显示。工单总SLA与当前节点SLA分别说明。示例节点明确是模拟返回；真实返回缺失时显示未提供，不推断。已移除把“FBB②…18个编排节点”混入SLA区域的设计；原业务“查看流程”功能仍保留，二者语义不同。

## 6. 主动服务：计划与执行独立

列表只展示已经创建的服务；模板不混在服务实例中。标题区提供“创建服务”和“查看模板”。创建先选择自定义或根据模板；模板预填内容、计划和时区，仍可编辑确认。独立模板目录可搜索、选择使用，并返回服务列表；仅显示当前AI有权使用的启用模板。

**计划状态**：草稿、已启用、已暂停、已结束。**最近执行**：排队/执行中/成功/部分成功/失败/超时/待补充/已取消。两者分别保留，已启用计划也可能当前没有执行，暂停未来计划不会取消已开始的执行。

服务筛选布局与我的业务一致。默认显示宽搜索及计划状态；更多筛选包含创建来源、执行频率、最近执行结果、当前环节、与我相关、授权部门/创建人和下次执行日期。模板目录通过独立入口进入，不再作为服务状态或服务视图选项。AI范围由入口固定。

| 操作 | 行为及约束 |
| --- | --- |
| 保存/编辑 | 保存新配置版本；旧运行的配置快照不改写；离开未保存内容前提示 |
| 立即运行 | 新建单次运行，存在在途运行时复用；不修改周期 |
| 暂停时运行 | 明确只执行一次，未来计划仍暂停 |
| 暂停/恢复计划 | 控制未来触发，不取消在途运行，不批量补跑 |
| 补充信息 | 校验后继续原运行，保留输入与来源 |
| 重试 | 保留历史与尝试次数，按策略限制；原型最多3次 |
| 取消执行 | 独立于停用计划；迟到结果不覆盖取消终态 |
| 分享 | 只读配置快照，可设置接收者、有效期、撤销；不授予执行权 |
| 删除服务 | 确认后移出有效列表，历史运行与来源审计仍保留 |

列表保留查看任务、编辑、立即运行、暂停、执行记录等操作。更多菜单浮层不受表格滚动容器遮挡。非本人服务即使可见也不因此获得修改、运行或删除权限。

运行中展示真实阶段与加载动效，不展示虚构百分比。成功只表示本次AI结果已生成，不能据此认定工单恢复、设备已操作或审批已通过。

## 7. AI 助手、协作和未读联动

### 7.1 卡片及筛选

沿用142的日期分组卡片布局；桌面每行3张，窄内容区按可用宽度适配。保留OSS业务、Big Data经营简报/telebirr分析，以及teleConnect会议/邮件示例。卡片统一展示时间、所属AI、分类、标题、整体状态、个人待办、当前环节、负责人、责任部门和详情入口。正文移入详情，不再让长说明或展开全文占满卡片。

分类为我的业务、主动服务、其他事件。默认宽搜索框加分类筛选；更多筛选包含阅读状态、所属AI、日期、整体状态、当前环节、与我相关、业务来源、SLA、事件类型和授权部门。所属AI按可用配置列出，无匹配提醒也不移除该AI选项；结果仍受业务权限约束。

阅读选项统一为 **全部状态 → 仅未读 → 仅已读**。其他选项先全部/不限，再按生命周期或稳定分类排列。SLA中正常、无SLA和待同步明确区分；SLA筛选依据关联任务当前状态，历史SLA提醒是独立事件类型。

### 7.2 运行中任务

正在运行的Cowork及主动服务进入AI助手，按稳定Run ID维持一张当前快照。进度更新只更新原卡片；自动运行不制造待我处理，也不在每次更新时产生未读。等待审批/补充使用明确环节和关联任务。完成或失败仍沿用结果/异常事件记录，不改变原任务处理权限。

打开运行中卡片进入对应AI的对应会话/运行，不消费未来的完成未读。历史中断记录保留，但不会作为新运行任务反复加入。自动执行结束不等于关联业务整体完成。

### 7.3 未读与计数

| 位置 | 统计单位 | 阅读后变化 |
| --- | --- | --- |
| 我的业务顶部红标 | 当前AI有未读更新的业务项，按业务键去重 | 查看一项，扣减一项 |
| 主动服务顶部红标 | 当前AI有未读运行结果的服务项 | 查看服务项/结果，消费关联提醒 |
| AI助手数字 | 可见的未读提醒事件 | 查看相应事件后减少 |
| Agent外层数字 | 含未读Cowork完成结果的会话数 | 该会话结果全部读完后减1 |
| Chat History蓝点 | 会话存在未读完成结果 | 全部读完移除蓝点 |
| AI气泡红标 | 可见的未读完成结果条数 | 打开目标结果后减少 |
| 我的AI分组红点 | 是否有需要关注的未读 | 展开后由各AI显示各自信息 |

例如同一会话有两个未读结果：会话数字为1，结果数字为2。读一个结果后会话蓝点仍在，不能为数字相同而混淆统计对象。

未读项进入业务/服务列表时优先展示，用蓝点和“未读更新”标识，不使用红框。当前访问期间查看后保持行位置，重新进入时重新排列剩余未读。红标按钮进入当前AI对应模块，清理阻挡定位的条件并定位未读；图标主体正常进入列表，不改跳AI助手。

详情打开或条目至少60%可见并持续1.5秒后按已有规则回执；隐藏页、被模态框或气泡遮挡的列表不自动消费。未查看的分页保持未读。筛选、固定图标、展开菜单不代表阅读。查看任务只清消息，不能代替审批、执行或SLA恢复。

### 7.4 正在协作与完成通知

气泡菜单顶部“正在协作”，下方“我的AI”及原工具；不再增加我的业务或显示任务提醒项。正在协作默认收起，悬停/点击后侧向展开，独立滚动，数量右对齐，主菜单不随任务数拉长。支持会话与定时服务，运行中显示loading，等待/中断显示对应说明。

点击会话按AI、session、run定位；点击服务进入该次运行会话。多个同名任务不能按标题猜测。切换保留其他会话草稿和附件，目标及动作重新校验权限。

新完成事件在右下角弹出“某任务已完成”，显示所属AI，6秒自动消失；唯一交互是点击进入对应会话/任务上下文。多个完成事件依次展示，重绘不延长计时，旧存档不重播，切身份不泄露原用户消息。提示消失不等于已读。不再维护第二套可展开的完成任务列表。

### 7.5 对话协作与报告

用户在右、AI在左。执行过程采用可折叠文字事件，运行时显示当前步骤；完成时显示一次总结及报告入口，推荐问题固定在消息末尾。保留暂停/恢复、等待补充、关联审批、记录、复制、反馈、分享等操作。这里显示的是可观察执行事件，不是模型内部思维链。

OSS示例为告警证据、光路排查与恢复验证；Big Data为经营口径核对、对比图表与分析报告；teleConnect为会议纪要与行动项。报告可预览、查看证据表并下载Markdown；演示数据明确为模拟值。非预置对话使用本次保存的真实输入/结果，不套用无关领域示例。



## 8. 审批、SLA与联系催办

### 8.1 审批

任务详情显示申请操作、申请人、指定审批人、风险依据、影响范围、输入快照、截止时间、状态和审批记录。指定且有能力的审批人可提交意见；通过后进入待执行/验证，不能直接当作业务完成。拒绝、补充和重复提交需遵循当前状态与修订校验。

审批结果通知指向同一任务/审批记录。当前任务数量不因挂审批单重复累加；处理权限和审批权限独立。转派按原策略审批，审批中SLA继续计时。

### 8.2 SLA来源和提醒

OSS提供工单总截止、当前节点、节点截止、节点负责人、联系人、修订及同步时间。临期为进入阈值但未超时，逾期为超过截止且未完成；“时限提醒”是通知类别，不是第三种SLA状态。节点时限优先表达当前处理责任，总SLA表达工单整体约束。

临期与逾期条件可以清除/切换/重置；阅读提醒、审批等待、催办、转派不暂停或重置SLA。过期联系人快照在演示中可自动模拟刷新；生产必须调用真实查询并处理失败，不能仅修改时间戳。

### 8.3 渠道选择及完整流程

| 联系资料 | 可用路径 | 展示步骤 |
| --- | --- | --- |
| 已验证teleConnect账号 | 快速消息 | 编辑消息 → 收件人/内容预览 → 明确确认 → 模拟回执与记录 |
| 有邮件 | AI起草邮件 | 输入写作要求 → 生成主题/正文 → 编辑 → 预览 → 确认发送（模拟） |
| 有电话 | 快速拨号、AI起草短信 | 号码确认/交接拨号器示意，或短信编辑/段数估算/预览/确认 |
| 信息不足 | 补充/同步资料 | 说明缺少哪项，不生成虚假可用渠道 |

联系对象为当前节点责任人，不一定是工单最初负责人。可按授权为客户联系人创建会议邀请并选择可用渠道，不自动给所有人群发。任务结束、权限变化、联系人更新等在确认前重新检查。

### 8.4 会议邀请

在消息/邮件/短信草稿中快捷创建会议，可设置主题、时间和时区，将邀请文字及链接插入草稿。展示邀请者、Title、Ethiopia Time（GMT+03:00）、Meeting ID和Join链接。用户提供的会议链接仅作格式参考，不重复使用为每次新会议。创建/编辑草稿与发送分开；取消发送不会伪造已送达。

记录渠道、目标、内容快照、会议关联、操作人、时间、发送/失败/模拟回执及重试。短信段数是估算，真实编码、费用和投递由网关决定。纯HTML未发出真实teleConnect消息、邮件、短信或电话，未创建真实会议。

## 9. 后台管理、任务看板和审计

### 9.1 后台任务看板

保留统一统计与任务跟踪能力，以表格、搜索、授权部门/成员筛选、状态/来源/AI/日期及分页为主，详情按需展开；不把大量任务全部平铺长卡片。看板可作为辅助视图，不替代大数据量列表。详情复用同一业务、审批、SLA和运行关联，角色过滤与统计同源。

### 9.2 主动服务运行记录

表格展示：服务名、Run ID、AI、责任部门、状态、触发方式、发起人、服务负责人、开始/结束时间、耗时（含排队/等待）、配置版本。手动发起人与负责人分列；系统计划标记系统调度；历史字段缺失显示未记录。

支持名称/编号、AI、状态、触发方式、日期；有组织权限时支持授权部门、负责人和发起人。先权限过滤再统计分页，支持10/20/50条分页。保留运行详情、来源、补充、重试历史及模拟调度。

### 9.3 创建来源会话与Q&A Log

后台不提供“在会话中继续”跳客户端。主动服务实例的**创建来源会话**进入后台Audit Center → Q&A Log，打开Dialogue Details右侧抽屉。

- 服务创建会话：展示哪个会话如何形成服务，包括提出需求、澄清范围/时间、计划回显、用户确认及最终创建配置。
- 运行问答记录：展示某次运行请求、补充、结果、来源和执行时间线。不能把运行日志冒充创建聊天。
- 列表保留Session Name、Q&A Type、Agent Type、Chat mode、Operator Name、Operator Phone、Session Start/End Time及Action，并关联Service ID、Run ID、Trace ID。
- 对话按用户/AI分侧展示，包含消息时间、创建者、会话标识和确认配置版本。没有数据不补造。
- 新建时保存来源快照；后续编辑不能改写原创建证据。后台表单创建明确标记，旧记录未保存来源明确说明缺失。
- 原型LOCAL Trace与示例对话用于演示。生产应以真实session_id/message_id范围、service_id、确认消息、版本和trace_id关联，并做服务端审计授权与脱敏。

## 10. 业务实例、场景模板与配置检查

### 10.1 实例发布场景模板

业务实例增加发布为场景模板流程：选择实例 → 检查可发布条件 → 填写模板名称/分类/说明、可参数化项 → 检查范围/敏感实例信息 → 预览 → 确认发布版本。模板复用流程配置与允许的参数，不复制工单实时状态、历史审批结论、执行结果或实例责任人私有信息。

已有实例固定原快照；模板后续升级不悄悄改变已运行实例。冲突、缺项、无权限和检查不通过应反馈明确原因。新实例使用模板时重新选择对象、角色和参数，不沿用原运行授权。

### 10.2 检查通过的边界

复用1019的结构化检查思路，将配置检查、试运行、审批和真实执行分别表达。检查内容包括结构连线、必填项、对象/能力绑定、参数与输入、审批/负责人、异常分支及可能的路径风险。

检查报告显示项、级别、定位与整改建议。配置修改后旧检查结论失效；试运行固定版本、输入、路径、来源及结果。配置检查通过仅说明当前静态条件满足，不表示真实数据源已连通、真实命令已执行或生产审批已通过。

## 11. 文件、上下文、分享与原有聊天

文件AI选择器修复滚动裁切，显示于可见浮层。文件问答选AI后沿用独立窗口和私有草稿流程；群聊发送前确认，不自动把AI回答发给所有成员。

文件有解析状态、版本、来源与引用位置。原型支持有限的DOCX/XLSX/PPTX/TXT/CSV提取；复杂文件、旧Office格式、PDF/OCR、公式计算等需真实解析服务。处理失败和无权限不可伪装为已成功解析。附件数量/大小遵循原型当前限制，生产需统一服务端校验。

私有草稿允许改问题、改回答、重生成、取消和确认发送；问题变更后旧答案需重新生成或明确过期。会话分享为消息快照，答案/配置分享只读；有效期、撤销及接收者权限独立，不转移文件权限。跨浏览器分享依赖后续服务端存储，当前本地链接不能等同跨设备共享。

输入区不再常驻“上下文：仅本次问题与附件”“文件与解析状态”两个占位按钮；相关能力通过适用的附件/AI范围设置及文件入口呈现。原有聊天消息、文件、历史与分享能力保留。

## 12. 嵌入teleConnect及生产接口边界

### 12.1 HTML当前可以展示

页面内的列表/筛选/跳转、模拟身份范围、通知和未读、运行/审批状态、催办编辑预览确认、会议格式、草稿保护、数据持久化、来源审计、Mac/Windows通知效果说明。

### 12.2 必须真实接入后完成

| 领域 | 开发接入责任 |
| --- | --- |
| 身份/权限 | 宿主登录凭据、租户/组织/角色、授权AI、服务端数据与动作校验 |
| OSS | 工单和节点SLA、责任人及联系方式、修订、状态同步与真实节点时间 |
| AI执行/调度 | 服务端计划执行、并发幂等、运行事件、断线恢复、取消及重试竞态 |
| 消息/邮件/短信/电话 | 发送API、收件人确认、渠道能力与失败回执、原生拨号交接 |
| 会议 | 真实会议创建、有效ID/链接、时区和邀请记录 |
| 审批/执行 | 真实审批策略、指定审批人、执行与验证、不可伪造的审计 |
| 通知 | 跨设备通知账本、eventId去重、已读回执、消息补拉、用户偏好 |
| 文件/分享 | 文件对象、版本/hash、解析服务、引用权限、跨设备快照访问 |
| 嵌入页面 | 宿主就绪/失败/登录失效事件、允许来源校验、窗口及消息桥接 |

Mac通知中心/Dock徽标与Windows Toast/任务栏闪烁由实际客户端实现；网页只演示效果，不声称改变真实操作系统状态。系统拒绝/勿扰不丢应用内消息；激活应用不等于阅读全部。客户端完全退出后的任务由服务端继续，不能依靠已关闭HTML。

### 12.3 核心标识与一致性

至少区分user_id、bot_id、session_id、task_id、review_id、service_id、run_id、配置版本、notification_id/event_id、trace_id。路由不要使用显示名称代替稳定主键。

配置/任务变更携带expectedVersion，运行固定快照，权限按实时重新校验。完成、通知投递、已读、审批、工单修复均独立。后台审计只读；不能通过读审计替用户确认或触发发送。

建议消息载荷包含事件ID、接收者、AI、类别、目标类型/ID、发生时间及必要的隐私展示字段。详情以接口重新查询并校验，不把令牌和完整业务正文放入公开链接。此处为开发契约建议，不代表已有同名接口。

## 13. 统一演示面板

左下角只有一个“演示面板”入口，不再按版本区分交互演示与演示设置。面板采用“身份与AI → 场景 → 步骤与结果”布局；原检查能力汇入场景或高级工具，没有删除原业务功能。

| 场景 | 演示路径 | 观察重点 |
| --- | --- | --- |
| 会话协作 | 准备场景 → 推进一步 → 查看原场景/AI助手 → 模拟完成 | 原会话、折叠过程、报告、短暂通知与未读 |
| 定时服务 | 准备场景 → 分步执行 → 查看运行会话 → 模拟完成 | 计划与执行独立，正在协作包含服务 |
| 审批待办 | 加载既有角色示例 → 进行中+待我审批 → 任务详情 | 指定审批人可操作，查看不等于通过 |
| SLA催办 | 四种联系人示例 → SLA节点 → 联系/催办 → 草稿预览 | 资料、渠道资格、确认和模拟回执 |
| 未读联动 | 使用多AI示例 → 未读项/卡片/历史 → 查看详情 | 事件、业务项、会话三种计数各自一致 |
| 权限范围 | 角色示例 → 切换身份 → 比较列表与详情 | 部门、成员、AI范围与审批能力 |
| 文件问答 | 文件解析示例 → 选AI → 编辑私有草稿 | 解析状态、内容范围及发送确认 |

会话及定时服务按当前身份+AI+场景复用本轮示例，多次准备不会不断增加副本。每个领域只保留代表性路径；历史记录继续可查。面板可中途关闭，重新打开后恢复本轮状态。“查看原场景”定位原run，不重新触发执行。分步任务不会因等待几分钟自动跑完，方便展示。

高级检查默认折叠，包含权限说明、Mac/Windows通知效果、连接中断/恢复、模拟调度、文件状态、分享管理、发送失败、嵌入说明、分页数据、历史示例及数据备份；内嵌页可模拟正常/加载/失败/登录失效。触发外发类场景只生成本地模拟，不发送真实消息。

不同浏览器、file、localhost、端口及GitHub Pages的本地存储独立。同一页面刷新不会重置已读。演示身份切换是观察权限的工具，不是生产登录；管理员演示需要明确选择身份。

## 14. 验收路径与维护

1. 打开演示面板，选Chang/OSS，准备会话，推进一步，在AI助手确认同一运行卡片与loading；跳转原会话后模拟完成，确认完成通知、报告和未读回执。
2. 切到定时服务，准备并推进同一run；暂停计划后该run仍在途，完成后未来计划保持暂停。打开运行会话不跳到创建服务的旧会话。
3. 审批场景：整体状态进行中+待我审批仅返回当前指定审批人的记录；阅读后红标减少，但待我审批仍在。通过审批后执行/验证仍需后续步骤。
4. 更多筛选组合状态、环节、关系、日期和SLA；确认交集、空状态、重置、页码以及权限范围。运行快照不因刷新或筛选新增未读。
5. 主动服务创建→自定义/模板→编辑保存；模板目录返回服务列表；查看未读项、详情、运行、来源审计和菜单浮层。
6. 切换可访问Big Data和teleConnect的身份，重复协作/报告/提醒路径，确认领域内容和授权不同，能力入口保持一致。
7. 后台验证部门成员筛选、表格分页、审批详情、运行耗时及创建来源Q&A；后台不跨跳客户端或代替客户端已读。
8. 保留群聊、私聊、附件、@AI、历史重命名/删除/分享、草稿、报告和转派等回归检查。

构建保留历史HTML，当前迭代基于上一版追加受控调整；发布前验证脚本、权限与运行链路，再进行浏览器关键交互检查。原型代码是累计交互验证稿，生产开发应将身份/权限、任务、计划/执行、通知回执、会话路由及审计拆分为明确服务和组件，不能直接把演示存储当作后端。

公开仓库允许查看、下载及Fork。没有写权限的同事先Fork，推送到自己仓库，再向主仓库提交Pull Request；直接推送主仓库需要仓库所有者授予协作者写权限。操作方式见 [CONTRIBUTING.md](CONTRIBUTING.md)。
